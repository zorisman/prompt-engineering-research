* Проблема
Передавая промпт языковой модели, вообще в любых случаях может создаваться неопределенность, из-за которой она точно не понимает, какой метод применять для решения задачи. Допустим, даже простейший промпт "add CONTRIBUTION.md into README.org" нейросеть может попытаться решать несколькими способами:
1. awk
2. sed
3. Инструменты харнесса
4. Иные способы записи в файл

Даже если указать необходимый способ, создается неопределенность: какие флаги использовать, и т.д.

* Метод 1 - Расширение математической логики
Возьмем традиционную запись математической логики:
P(X) = <statement>

Statement может означать вообще все что угодно из-за нестрогости в определении, что и создает вышеописанную проблему. Разобьем высказывание на подмножество меньших по задачности высказываний:
P(X) = A(X)

Обычно алгоритмы имеют что-то делает с входными данными и выдают выходные данные. Покажем это в виде отображения функции:
P(X) = A(X) -> Y

Алгоритм может требовать набор предусловий и постусловий. Добавим логику Хоара:
P(X) = {C_{pre}} A(X) -> Y {C_{post}}

Теперь у нас возникает еще одна проблема. Каким образом языковая модель должна выполнять все логические члены? Для этого можно ввести ограничения.

** Вариант ограничений А
Добавляем в логическую запись ограничения в виде S(Z)
P(X) = {C_{pre}} A(X) -> Y {C_{post}} |_{C_{pre} = S(Z), ...}

Для каждого логического члена должна описываться одни и те же ограничения. При неприменимости предлагается записывать "решений нет".

В качестве примера используем все то же выражение "add CONTRIBUTION.md into README.org". Его можно разбить на логическую последовательность:
1. Что сделать? - add
2. Над чем это сделать? - CONTRIBUTION.md
3. Куда применить результат (отображение A(X))? - into README.org

Здесь упускается важная деталь: Как это сделать?

На данный момент можно использовать следующий шаблон записи:
{
  1. What - Wh(X_h)
  2. Work on - Wo(X_r) -> Y
  3. Apply on - $Ao(Y, L)$, где:
     - L - множество некоторых членов, над которыми нужно применить множество данных Y
  4. How to ("What, Work on, Apply on") - Ht(Wh, Wo, Ao) - Как работать над первыми тремя операциями
}

*** Apply on
Для проверки применимости Y к L, строим декартово произведение:
D = Y x L = (y_n, l_n)

Ради обеспечения наглядности, по строкам стоит распределить выходные данные, а по столбцам - члены, к которым эти данные применяются. Тем не менее, задачу можно представить в матричном виде.

Пусть Y = (a, b, c), L = (x, y, z)
(a, x) (a, y) (a, z)
(b, x) (b, y) (b, z)
(c, x) (c, y) (c, z)

Данную матрицу предлагается назвать *матрицей допустимых задач*.

В соответствие данной матрице необходимо построить матрицу выполнимости задачи от 0 до 1, где 0 означает ненужность выполнимости, а 1 - необходимость выполнимости. Значения между 0 и 1 задают вероятность того, насколько данное решение может понадобиться. Например, задача с весом 0.5 не необходима, но будет полезной. Задача с весом 0.99 почти необходима, но алгоритм может обойтись без нее. Данную матрицу предлагается назвать *матрицей важностей*

На основе матрицы важностей строится окончательное синтаксическое представление задачи. Предположим, что из матрица Y может выполнить задачу в полной мере в случае, если элементы по диагонали необходимы, остальныые элементы не нужны. Получаем:
$S* = a_{11} \land a_{22} \land a_{33}$
